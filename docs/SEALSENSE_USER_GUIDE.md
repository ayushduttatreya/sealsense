## 1. Starting SealSense

### Quick Start (Automated Script)
The simplest way to start all services is using the included launcher:

```bash
# Navigate to the repository root
cd /home/ayush/Projects/sealsense

# Run the unified demonstration startup script
./scripts/start_demo.sh
```

### Manual Service Startup
If you prefer running services in separate terminal windows:

#### Terminal 1 — Backend (FastAPI + Uvicorn)
```bash
cd /home/ayush/Projects/sealsense/backend
.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```
*Confirmation:* Open [http://localhost:8000/health](http://localhost:8000/health) — it should return `{"status":"ok","version":"0.2.0"}`.

#### Terminal 2 — Frontend (React + Vite)
```bash
cd /home/ayush/Projects/sealsense
npm run dev
```
*Confirmation:* Open [http://localhost:5173](http://localhost:5173) in your web browser.

### Local URLs Reference
| Component | Local URL | Description |
|:---|:---|:---|
| **Operator Console** | [http://localhost:5173](http://localhost:5173) | Main React Web UI |
| **FastAPI Swagger Docs** | [http://localhost:8000/docs](http://localhost:8000/docs) | Interactive API exploration |
| **OpenAPI Specification** | [http://localhost:8000/openapi.json](http://localhost:8000/openapi.json) | Raw JSON API schema |
| **Health Check** | [http://localhost:8000/health](http://localhost:8000/health) | Backend liveness probe |

### Stopping Services Safely
- Press `Ctrl+C` in the terminal running `./scripts/start_demo.sh`. Both frontend and backend will be gracefully terminated.
- SQLite transactions commit automatically upon request completion; stopping the server will not corrupt the database.

## 2. Understanding the Dashboard Metrics & Badges

### Metric Cards (Overview Page)
- **Active Zones**: Total storage zones registered in the facility (e.g., `Zone A — Silo 1`, `Zone B — Silo 2`, `Zone C — Silo 3`).
- **Connected Nodes**: Count of ESP32 sensor nodes that have reported telemetry within their `inactivity_timeout_sec` (300 seconds).
- **Active Alarms**: Unacknowledged or active alarms requiring operator intervention.
- **Acoustic Events**: Total bioacoustic events detected or processed in the system.

### Sensor & Data Badges
- `REAL` / `HARDWARE`: Genuine physical telemetry measured by attached hardware (e.g., INMP441 audio).
- `DEMO` / `SIMULATED`: Environmental series generated by the deterministic scenario engine for demonstration purposes.
- `MODEL_EXPERIMENT`: Bioacoustic predictions generated by `nocturne-v1-mini`. Labeled experimental because Nocturne Mini was trained on outdoor nocturnal wildlife, not stored-grain insects.
- `INSUFFICIENT VALIDATION DATA`: Displayed when field microphone validation sets lack sufficient verified ground-truth labels. Prevents displaying unscientific accuracy claims.

## 3. Using Every Major Page

### Overview Console
- **Purpose**: High-level facility operational dashboard.
- **What to look at**:
  - The top summary metric bar.
  - The **Storage Zones Grid**: Shows current environmental conditions (CO₂, Temperature, Air RH) and zone health (`healthy`, `warning`, `critical`).
  - The **Recent Events & Alarms Stream**: Shows active environmental and acoustic events.
- **Actions you can take**:
  - Switch demonstration scenarios via the top-right scenario dropdown (`Healthy Storage`, `Rising Environmental Risk`, `Acoustic Pest Event`, `Combined Critical Warning`).
  - Click on any zone to navigate directly to its detailed telemetry.

### Storage Zones
- **Purpose**: Deep-dive telemetry inspection for individual silos.
- **What to look at**:
  - Real-time time-series charts showing CO₂ concentration ($ppm$), Temperature ($^\circ C$), and Air Relative Humidity ($\% RH$).
  - *Domain Guardrail Note:* Air RH measures the relative humidity of the headspace air, **not** grain moisture content ($MC_{wb}$). The interface prominently notes this physical distinction.
- **Actions you can take**:
  - Filter readings by 1-hour, 6-hour, 24-hour, or 7-day aggregation windows.
  - Inspect downsampled data rollups calculated via continuous time-bucket averaging.

### Acoustic Monitoring
- **Purpose**: Primary audio analysis, inference demonstration, and dataset management console.
- **Three Core Tabs**:
  1. **Upload & Live Inference**:
     - Drag-and-drop any WAV recording or use captured physical hardware audio.
     - View interactive waveform visualizer and multi-band spectrogram peaks.
     - Inspect calculated acoustic features: RMS Energy, Peak Amplitude, Spectral Centroid ($Hz$), Spectral Bandwidth ($Hz$), Spectral Flatness (Wiener entropy), Zero-Crossing Rate, and Hilbert/MAD Transient Impulse counts.
     - Review Nocturne Mini inference output (Predicted Species, Confidence Band, Top-5 Probabilities) labeled as an *Experimental Research Classifier*.
  2. **USDA Reference Catalog**:
     - Browse genuine USDA ARS Bug Bytes reference recordings (*Sitophilus oryzae*, *Plodia interpunctella*).
     - Inspect verified transducer physics (`accelerometer`, `pvdf`, `piezoelectric`, `ultrasonic_transducer`).
     - Click **"Inspect Signal Features"** to calculate physical acoustic metrics directly on the original scientific recording.
     - Import any reference recording into the dataset library with preserved provenance.
  3. **Dataset Library & Scientific Evaluation**:
     - Review all retained recordings (Hardware, USDA Reference, and Synthetic).
     - Filter by recording domain (`airborne_microphone`, `accelerometer`, `pvdf`, etc.).
     - View validation readiness: displays `INSUFFICIENT VALIDATION DATA` banner to prevent false accuracy claims while field microphone datasets are being curated.

### Alerts & Events
- **Purpose**: ThingsBoard-style 4-state alarm lifecycle and Frigate-style event triage.
- **4-State Lifecycle**:
  - `active_unack`: Alarm triggered, awaiting operator acknowledgment.
  - `active_ack`: Operator has acknowledged the condition; alarm remains active until environmental or acoustic threat clears.
  - `cleared_unack`: Condition returned to normal, but operator has not acknowledged the incident.
  - `cleared_ack`: Incident fully resolved and acknowledged.
- **Actions you can take**:
  - Click **"Acknowledge"** on any active alert.
  - Click **"Clear / Resolve"** to mark an alert resolved.
  - Click **"Inspect Automation Trace"** to view the Home Assistant-style step-by-step trigger $\to$ condition $\to$ action execution trace.
  - Human validation: Mark acoustic events as `VALIDATED` (pest confirmed) or `REJECTED` (false positive) with reviewer notes.

### Devices & Sensor Mesh
- **Purpose**: Hardware status and connectivity monitoring.
- **What to look at**:
  - `esp32-zone-a-01`: Assigned to Zone A.
  - **INMP441 Microphone**: Displays `OK` (Hardware active and verified responsive on GPIO 25/26/33).
  - **SCD41 CO₂ Sensor**: Displays `NOT CONNECTED (Hardware Unpopulated)`. Live CO₂ telemetry is disabled, preventing fabricated sensor data.
  - **Buzzer**: Connected to GPIO 27 for local rule-based acoustic alerting.
  - Inactivity monitor: Displays last-seen timestamp and dynamic timeout countdown.

## 4. Working with Audio & the Hardware Microphone

### Hardware Connection & Pinout
Connect the INMP441 I²S microphone to the ESP32 DevKit as follows:

| INMP441 Pin | ESP32 GPIO | Description |
|:---|:---|:---|
| **L/R** | **GND** | Tied to GND $\to$ Transmits on Left Channel (Slot 0) |
| **WS / LRCL** | **GPIO 25** | Word Select (16 kHz square wave) |
| **SCK / BCLK** | **GPIO 26** | Bit Clock (1.024 MHz) |
| **GND** | **GND** | Common Ground |
| **VDD** | **3.3V** | Regulated 3.3V Power |
| **SD** | **GPIO 33** | Serial Data (I²S Audio Input) |

### Uploading the Streaming Diagnostic Firmware
Before capturing recordings, ensure the diagnostic firmware is flashed to your ESP32:

```bash
# Set port permissions
sudo chmod 666 /dev/ttyUSB0

# Compile and upload the INMP441 diagnostic firmware
arduino-cli compile --fqbn esp32:esp32:esp32 firmware/inmp441_diagnostic
arduino-cli upload -p /dev/ttyUSB0 --fqbn esp32:esp32:esp32 firmware/inmp441_diagnostic
```

### Capturing Genuine 16 kHz Audio with the Host Tool
SealSense includes a dedicated host-side capture utility: [tools/capture_inmp441.py](file:///home/ayush/Projects/sealsense/tools/capture_inmp441.py).

```bash
# Capture a 10-second genuine recording and automatically upload to backend
backend/.venv/bin/python tools/capture_inmp441.py --port /dev/ttyUSB0 --duration 10 --upload

# Or capture without automatic upload:
backend/.venv/bin/python tools/capture_inmp441.py --port /dev/ttyUSB0 --duration 10 --no-upload
```

#### What the capture script does:
1. Connects to `/dev/ttyUSB0` at 115,200 baud.
2. Sends the framed trigger command `CAPTURE_WAV:10\n`.
3. Streams exactly 320,044 binary bytes (44-byte WAV header + 160,000 samples of 16-bit PCM).
4. Saves the recording to [backend/data/hardware_recordings/](file:///home/ayush/Projects/sealsense/backend/data/hardware_recordings/).
5. Generates companion JSON metadata preserving physical hardware provenance.
6. Ingests the file into the SealSense API (`POST /api/inference/acoustic/upload`), running Nocturne Mini inference and physical signal analysis automatically.

## 5. Device Management & SCD41 Limitations

### SCD41 Sensor Absence
- The physical SCD41 photoacoustic CO₂ and climate sensor is currently **not connected**.
- In accordance with SealSense data integrity principles, **no live CO₂ readings are fabricated**.
- The Devices page explicitly marks the SCD41 as `NOT CONNECTED (Hardware Unpopulated)`.
- Environmental charts on the Overview and Storage Zones pages display deterministic demonstration scenarios labeled `DEMO / SIMULATED`.

## 6. Alerts & Human-in-the-Loop Validation

### Managing Alerts
1. Open the **Alerts & Events** page.
2. Under **Active Alarms**, locate an alert (e.g., `CO₂ elevated in Zone A`).
3. Click **"Acknowledge"** $\to$ Alarm transitions from `active_unack` to `active_ack`.
4. Click **"Clear / Resolve"** $\to$ Alarm transitions to `cleared_ack` and moves to the resolved history log.

### Validating Acoustic Events (Frigate Review Lifecycle)
1. In the **Acoustic Events** table, click on an event.
2. Review the audio waveform and the calculated physical signal characteristics.
3. In the Review Drawer:
   - Select **Target Pest Observed** if physical grain inspection confirmed weevils/borers.
   - Select **No Target Pest Observed** if inspection confirmed an empty or uninfested sample.
   - Select **Inconclusive** if trap results are pending.
4. Enter your reviewer name and notes, then click **"Submit Validation"**.
5. The review status updates from `unreviewed` to `reviewed`, updating the scientific audit trail.

## 7. Troubleshooting Guide

### 1. Serial Port Permission Denied (`/dev/ttyUSB0`)
**Symptom:** `PermissionError: [Errno 13] Permission denied: '/dev/ttyUSB0'`  
**Fix:**
```bash
sudo chmod 666 /dev/ttyUSB0
# Or permanently add your user to dialout:
sudo usermod -a -G dialout $USER
```

### 2. Backend Port 8000 Already in Use
**Symptom:** `ERROR: [Errno 98] Address already in use`  
**Fix:**
```bash
# Find and terminate old uvicorn process
fuser -k 8000/tcp
```

### 3. Frontend Port 5173 Collision
**Symptom:** Vite starts on port 5174 instead of 5173.  
**Fix:**
```bash
fuser -k 5173/tcp
npm run dev
```

### 4. ESP32 Streaming Timeout
**Symptom:** `capture_inmp441.py` reports `Timeout waiting for >>>BEGIN_WAV<<< marker`.  
**Fix:**
1. Ensure the ESP32 DevKit is running `firmware/inmp441_diagnostic`.
2. Check that no other serial monitor (e.g., Arduino IDE, minicom) is currently holding `/dev/ttyUSB0` open.

## 8. End-to-End Architecture Overview

```
[ INMP441 Microphone ] (I2S: BCLK=26, WS=25, SD=33)
         │
         ▼
[ ESP32 DevKit ] ──(USB Serial: /dev/ttyUSB0)──▶ [ tools/capture_inmp441.py ]
                                                          │
                                         (HTTP Multipart Upload)
                                                          │
                                                          ▼
[ FastAPI Backend (Port 8000) ]
   ├── Audio Storage Engine (SHA-256 Deduplication & WAV Validation)
   ├── Acoustic Signal Analyzer (RMS, Peak, Centroid, Bandwidth, Hilbert/MAD Clicks)
   ├── Nocturne Mini ML Adapter (160k Sample Tensor, Bioacoustic Inference)
   ├── Alert Rule Engine (ThingsBoard 4-State Lifecycle, Home Assistant Traces)
   └── SQLite Database (backend/sealsense.db)
         │
         ▼ (REST API / JSON)
[ React Frontend (Port 5173) ]
   ├── Overview Console (Zone Health & Metrics)
   ├── Storage Zones (Silo Climate Telemetry)
   ├── Acoustic Monitoring (Waveforms, Reference Catalog, Evaluation Console)
   ├── Alerts & Events (Operator Triage & Human Review)
   └── Devices & Sensors (Hardware Mesh Inventory)
```
